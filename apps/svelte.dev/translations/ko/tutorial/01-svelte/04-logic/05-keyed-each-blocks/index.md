---
title: 키 있는 each 블록
---

기본적으로 `each` 블록이 순회하는 목록이 업데이트되면, Svelte는 길이가 바뀐 경우 블록의 *끝*에서 DOM 노드를 추가하거나 제거하고, 나머지 DOM 노드는 그 자리에서 업데이트합니다. 이것이 원하는 동작이 아닐 수도 있습니다.

설명보다 직접 보는 편이 쉽습니다. `Thing.svelte` 안에서 `name`은 동적인 prop이지만 `emoji`는 상수입니다.

'Remove first thing' 버튼을 몇 번 클릭하고 무슨 일이 일어나는지 보세요:

1. 마지막 컴포넌트가 제거됩니다.
2. 그다음 남은 DOM 노드의 `name` 값이 업데이트되지만('doughnut'이 들어 있던 텍스트 노드에 이제 'egg'가 들어가는 식으로), 이모지는 업데이트되지 않습니다.

> [!NOTE] React를 써 왔다면 이상하게 보일 수 있습니다. 상태가 바뀌면 컴포넌트 전체가 다시 렌더링되는 데 익숙할 테니까요. Svelte는 다르게 동작합니다. 컴포넌트는 한 번 '실행'되고, 이후의 업데이트는 '세밀하게' 이루어집니다. 덕분에 더 빠르고 더 세밀하게 제어할 수 있습니다.

한 가지 해결책은 `emoji`를 [`$derived`](derived-state) 값으로 만드는 것입니다. 하지만 *마지막* 컴포넌트를 제거하고 나머지를 모두 업데이트하기보다는, 첫 번째 `<Thing>` 컴포넌트를 통째로 제거하는 편이 더 합리적입니다.

그러려면 `each` 블록의 각 반복마다 고유한 *키*를 지정합니다:

```svelte
/// file: App.svelte
{#each things as thing (+++thing.id+++)}
	<Thing name={thing.name}/>
{/each}
```

> [!NOTE] Svelte는 내부적으로 `Map`을 사용하므로 어떤 객체든 키로 쓸 수 있습니다. 즉, `(thing.id)` 대신 `(thing)`을 써도 됩니다. 하지만 보통은 문자열이나 숫자를 쓰는 편이 더 안전합니다. 예를 들어 API 서버에서 받은 새 데이터로 업데이트할 때처럼, 참조가 같지 않아도 동일성이 유지되기 때문입니다.
