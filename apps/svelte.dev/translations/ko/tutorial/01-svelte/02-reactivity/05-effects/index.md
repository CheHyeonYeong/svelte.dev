---
title: 이펙트
tags: rune-effect
---

지금까지는 상태의 관점에서 반응성을 이야기했습니다. 하지만 그건 절반에 불과합니다. 상태는 무언가가 그것에 *반응*할 때만 반응형이고, 그렇지 않으면 그저 평범한 변수일 뿐입니다.

반응하는 쪽을 *이펙트*라고 부릅니다. 이미 이펙트를 만난 적이 있습니다. 상태 변화에 따라 DOM을 업데이트하려고 Svelte가 대신 만들어 주는 이펙트 말이죠. 하지만 `$effect` 룬으로 직접 이펙트를 만들 수도 있습니다.

> [!NOTE] 대부분의 경우에는 직접 만들지 않는 것이 좋습니다. `$effect`는 자주 쓰는 도구가 아니라 탈출구라고 생각하는 편이 좋습니다. 예를 들어 부수 효과를 [이벤트 핸들러](dom-events)에 넣을 수 있다면 거의 항상 그쪽이 낫습니다.

`setInterval`을 사용해 컴포넌트가 마운트된 지 얼마나 지났는지 추적하고 싶다고 해 봅시다. 이펙트를 만드세요:

```svelte
/// file: App.svelte
<script>
	let elapsed = $state(0);
	let interval = $state(1000);

+++	$effect(() => {
		setInterval(() => {
			elapsed += 1;
		}, interval);
	});+++
</script>
```

'speed up' 버튼을 몇 번 클릭해 보면 `elapsed`가 더 빨리 올라가는 것을 볼 수 있습니다. `interval`이 작아질 때마다 `setInterval`을 호출하고 있기 때문입니다.

그다음 'slow down' 버튼을 클릭하면... 음, 동작하지 않습니다. 이펙트가 업데이트될 때 이전 인터벌을 정리하지 않기 때문입니다. 정리 함수를 반환하면 이 문제를 고칠 수 있습니다:

```js
/// file: App.svelte
$effect(() => {
	+++const id =+++ setInterval(() => {
		elapsed += 1;
	}, interval);

+++	return () => {
		clearInterval(id);
	};+++
});
```

정리 함수는 `interval`이 바뀌어 이펙트 함수가 다시 실행되기 직전과, 컴포넌트가 제거될 때 호출됩니다.

이펙트 함수가 실행될 때 아무 상태도 읽지 않는다면, 컴포넌트가 마운트될 때 한 번만 실행됩니다.

> [!NOTE] 이펙트는 서버 사이드 렌더링 중에는 실행되지 않습니다.
