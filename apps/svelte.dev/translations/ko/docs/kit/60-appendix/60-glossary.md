---
title: 용어집
---

SvelteKit의 핵심은 매우 유연하게 설정할 수 있는 렌더링 엔진입니다. 이 섹션에서는 렌더링을 이야기할 때 쓰는 몇 가지 용어를 설명합니다. 이 옵션들을 설정하는 방법에 대한 레퍼런스는 위의 문서에서 제공합니다.

## CSR

클라이언트 사이드 렌더링(CSR)은 JavaScript를 사용해 웹 브라우저에서 페이지 내용을 생성하는 것입니다.

SvelteKit에서는 기본적으로 클라이언트 사이드 렌더링을 사용하지만, [`csr = false` 페이지 옵션](page-options#csr)으로 JavaScript를 끌 수 있습니다.

## 엣지 <!-- Edge -->

엣지 렌더링은 사용자와 가까운 콘텐츠 전송 네트워크(CDN)에서 애플리케이션을 렌더링하는 것을 말합니다. 엣지 렌더링을 사용하면 페이지의 요청과 응답이 이동하는 거리가 짧아져 지연 시간이 줄어듭니다.

## 하이브리드 앱 <!-- Hybrid app -->

SvelteKit은 기본적으로 하이브리드 렌더링 모드를 사용합니다. 첫 HTML은 서버에서 로드하고(SSR), 이후 내비게이션에서는 클라이언트 사이드 렌더링(CSR)으로 페이지 내용을 업데이트합니다.

## 하이드레이션 <!-- Hydration -->

Svelte 컴포넌트는 상태를 저장하고, 상태가 업데이트되면 DOM을 업데이트합니다. SSR 중에 데이터를 가져오면, SvelteKit은 기본적으로 이 데이터를 저장해 서버 렌더링된 HTML과 함께 클라이언트로 전송합니다. 그러면 컴포넌트는 같은 API 엔드포인트를 다시 호출하지 않고도 그 데이터로 클라이언트에서 초기화될 수 있습니다. 그다음 Svelte는 DOM이 예상한 상태인지 확인하고 이벤트 리스너를 연결하는데, 이 과정을 하이드레이션이라고 합니다. 컴포넌트가 완전히 하이드레이트되면, 새로 만든 Svelte 컴포넌트와 똑같이 속성 변경에 반응할 수 있습니다.

SvelteKit에서는 기본적으로 페이지가 하이드레이트되지만, [`csr = false` 페이지 옵션](page-options#csr)으로 JavaScript를 끌 수 있습니다.

## ISR

증분 정적 재생성(ISR, Incremental static regeneration)을 사용하면 다시 배포하지 않고도 방문자가 요청할 때 사이트의 정적 페이지를 생성할 수 있습니다. 페이지가 많은 [SSG](#SSG) 사이트에 비해 빌드 시간을 줄일 수 있습니다. [`adapter-vercel`로 ISR](adapter-vercel#Incremental-Static-Regeneration)을 할 수 있습니다.

## MPA

JavaScript가 아닌 언어로 작성된 애플리케이션처럼 각 페이지 뷰를 서버에서 렌더링하는 전통적인 애플리케이션을 흔히 멀티 페이지 앱(MPA)이라고 부릅니다.

## 프리렌더링 <!-- Prerendering -->

프리렌더링은 빌드 시점에 페이지 내용을 계산하고, 표시할 HTML을 저장해 두는 것을 뜻합니다. 이 방식은 전통적인 서버 렌더링 페이지와 같은 이점이 있으면서도 방문자마다 페이지를 다시 계산하지 않으므로, 방문자 수가 늘어나도 거의 비용 없이 확장됩니다. 대신 빌드 과정의 비용이 더 크고, 프리렌더링된 콘텐츠는 애플리케이션의 새 버전을 빌드하고 배포해야만 업데이트할 수 있다는 단점이 있습니다.

콘텐츠를 프리렌더링할 수 있으려면, 그 콘텐츠에 직접 접근하는 어떤 두 사용자든 서버에서 같은 콘텐츠를 받아야 하며, 페이지에 [액션](form-actions)이 없어야 합니다. 모든 사용자가 같은 프리렌더링된 콘텐츠를 보기만 한다면, 페이지의 매개변수에 따라 로드되는 콘텐츠도 프리렌더링할 수 있습니다. 모든 페이지를 프리렌더링하는 것을 [정적 사이트 생성](#SSG)이라고도 합니다.

프리렌더링된 페이지가 정적 콘텐츠로만 제한되는 것은 아닙니다. 사용자별 데이터를 클라이언트 사이드에서 가져와 렌더링한다면 개인화된 페이지를 만들 수 있습니다. 다만 앞에서 설명한 것처럼, 그 콘텐츠에 대해서는 SSR을 하지 않는 데 따른 단점을 감수해야 합니다.

SvelteKit에서는 [`prerender` 페이지 옵션](page-options#prerender)과 `vite.config.js`에 있는 SvelteKit 플러그인의 [`prerender` 설정](@sveltejs-kit-vite#prerender)으로 프리렌더링을 제어할 수 있습니다.


## PWA

프로그레시브 웹 앱(PWA)은 웹 API와 기술로 만들었지만 모바일 앱이나 데스크톱 앱처럼 동작하는 앱입니다. [PWA로 제공되는 사이트는 설치할 수 있어서](https://web.dev/learn/pwa/installation) 런처, 홈 화면, 시작 메뉴에 애플리케이션 바로가기를 추가할 수 있습니다. 많은 PWA가 [서비스 워커](service-workers)를 활용해 오프라인 기능을 구현합니다.

## 라우팅 <!-- Routing -->

기본적으로 (링크를 클릭하거나 브라우저의 앞으로/뒤로 버튼을 사용해) 새 페이지로 이동하면, SvelteKit은 브라우저가 목적지 페이지를 서버에 요청하도록 두는 대신 그 내비게이션 시도를 가로채서 직접 처리합니다. 그다음 SvelteKit은 새 페이지의 컴포넌트를 렌더링해 클라이언트에 표시된 내용을 업데이트하며, 이 컴포넌트는 다시 필요한 API 엔드포인트를 호출할 수 있습니다. 이처럼 내비게이션 시도에 반응해 클라이언트에서 페이지를 업데이트하는 과정을 클라이언트 사이드 라우팅이라고 합니다.

SvelteKit에서는 기본적으로 클라이언트 사이드 라우팅을 사용하지만, [`data-sveltekit-reload`](link-options#data-sveltekit-reload)로 건너뛸 수 있습니다.

## SPA

싱글 페이지 앱(SPA)은 서버로 가는 모든 요청이 하나의 HTML 파일을 로드하고, 그 파일이 요청된 URL에 따라 클라이언트 사이드 렌더링을 하는 애플리케이션입니다. 모든 내비게이션은 클라이언트 사이드 라우팅이라는 과정을 통해 클라이언트 사이드에서 처리되며, 페이지별 내용은 업데이트되고 공통 레이아웃 요소는 대체로 그대로 유지됩니다. 이 사이트 전체에서 SPA라고 할 때는, 첫 요청에 빈 껍데기만 제공하는 앱이라는 이 정의를 사용합니다. 첫 요청에 HTML을 제공하는 [하이브리드 앱](#Hybrid-app)과 혼동하면 안 됩니다. SPA는 렌더링을 시작하기 전에 네트워크 왕복을 두 번 하게 만들기 때문에 성능에 큰 영향을 줍니다. SPA 모드는 성능과 SEO에 큰 악영향을 주므로, 모바일 앱으로 감싸는 경우처럼 매우 제한된 상황에서만 권장합니다.

SvelteKit에서는 [`adapter-static`으로 SPA를 빌드](single-page-apps)할 수 있습니다.

## SSG

정적 사이트 생성(SSG)은 모든 페이지가 프리렌더링된 사이트를 가리키는 용어입니다. 사이트를 완전히 프리렌더링하면 SSR을 수행할 서버를 유지하거나 비용을 낼 필요가 없다는 장점이 있습니다. 한 번 생성하면 사이트를 CDN에서 제공할 수 있어서 “첫 바이트까지의 시간(time to first byte)” 성능이 아주 좋습니다. 이런 제공 모델을 흔히 JAMstack이라고 부릅니다.

SvelteKit에서는 [`adapter-static`](adapter-static)을 사용하거나, [`prerender` 페이지 옵션](page-options#prerender) 또는 `vite.config.js`에 있는 SvelteKit 플러그인의 [`prerender` 설정](@sveltejs-kit-vite#prerender)으로 모든 페이지를 [프리렌더링](#Prerendering)하도록 설정해 정적 사이트를 생성할 수 있습니다.

## SSR

서버 사이드 렌더링(SSR)은 서버에서 페이지 내용을 생성하는 것입니다. 성능과 SEO 측면에서는 SSR이나 프리렌더링으로 서버에서 페이지 내용을 반환하는 방식이 훨씬 바람직합니다. SPA에서 필요한 추가 왕복을 피해 성능을 크게 높이고, JavaScript가 실패하거나 꺼져 있을 때도(이런 일은 [생각보다 자주 일어납니다](https://kryogenix.org/code/browser/everyonehasjs.html)) 사용자가 앱을 이용할 수 있게 해 줍니다. 일부 검색 엔진은 클라이언트 사이드에서 동적으로 생성된 콘텐츠도 색인할 수 있지만, 그런 경우에도 시간이 더 오래 걸릴 가능성이 큽니다.

SvelteKit에서는 기본적으로 페이지를 서버 사이드 렌더링합니다. [`ssr` 페이지 옵션](page-options#ssr)으로 SSR을 끌 수 있습니다.
